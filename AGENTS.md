# AGENTS.md - World Pixels

A huge shared pixel canvas on the web. Anyone opens the page, picks a color, and paints one pixel at a time (10 s cooldown). Everyone sees everyone else's pixels appear live. The backend is a **Supabase free-tier project** (Postgres + Realtime + Anonymous Auth). There is no custom server.

- `src/` has only `main.tsx`, a placeholder `App.tsx`, `index.css` and `env.d.ts`. `supabase/` does not exist yet.

## Core architecture rules

1. **All pixel writes go through the `place_pixel` RPC** (a `security definer` function). Clients never `insert`/`update` canvas tables, and RLS blocks it.
2. **The canvas is stored as chunks**: `canvas_chunks(cx, cy, data bytea, seq)`. One byte per pixel holds a palette index. No row per pixel, no pixel history log.
3. **Live updates are Realtime Broadcast sent by Postgres** (`realtime.send`) on the private topic `canvas`. Never Postgres Changes, and clients never broadcast pixels.
4. **Client load order:** sign in anonymously -> subscribe (buffer events) -> load snapshot -> apply buffered events newer than each chunk's `seq` -> live.
   After any reconnect, load the snapshot again.
5. **Constants are defined twice**: in SQL (inside `place_pixel`) and in `src/config.ts`. Change both in the same task.
6. **Free tier is a hard constraint.** Check Realtime fan-out, egress and database size before adding anything. See the `supabase-free-tier` skill.

## React rules (details and code templates: `vite-app` skill)

1. **React draws the UI around the canvas; it never touches pixels.** Pixels, the viewport, timers and the Supabase channel live in plain TS
   (`src/canvas/`, `src/realtime/`, `src/engine.ts`). Never keep pixels, chunks or the viewport in React state, props or context.
2. **One bridge:** `src/store.ts` holds the small app state (selected color, status, notice, cooldown seconds). Components read it with
   `useAppState()` and change it with `setState()`. The engine reads and writes the same store. No React context, no other global state.
3. **The canvas engine starts in exactly one effect**: `useEffect(() => startWorld(ref.current!), [])` in `CanvasView`. `startWorld` returns
   `stop()`, which removes the channel, listeners and timers. `<StrictMode>` runs it as start, stop, start in dev.
4. Function components, **named exports**, one component per file in `src/components/`, file name = component name (`Palette.tsx`).
5. Styles: `src/index.css` for global rules only. Each component uses its own CSS Module, `Palette.module.css`, imported as `styles`.
6. React 19: `ref` is a normal prop (never `forwardRef`), no `import React` (automatic JSX runtime), no `defaultProps` (use default parameters),
   no `propTypes`. Don't use `use()`, Suspense, Actions, `useActionState` or `useOptimistic` in v1: there is no async React data.
7. Pointer and wheel input are native listeners in `src/canvas/input.ts`, not React `onPointerDown` / `onWheel` props (React's wheel listener is
   passive, so `preventDefault()` fails).

## Code conventions

- Relative imports include the extension: `import { App } from './App.tsx'`, `import { CHUNK } from '../config.ts'`.
- Type-only imports use `import type` (or an inline `type` modifier). TS rejects `enum`, `namespace` and constructor parameter properties: use
  `as const` objects and union types.
- Named exports everywhere. The only default export is `vite.config.ts`.
- Style follows the template: single quotes, no semicolons, 2-space indent, trailing commas, lines up to 150 characters.

## Security boundaries

- Only the **publishable/anon key** goes in the client. Never put the `service_role` / `sb_secret_...` key in `src/`, in a `VITE_*` variable, or in a
  commit.
- RLS is enabled on every table in `public`. A table with RLS on and no policies is intentional (only definer functions may touch it).
- Every `security definer` function sets `search_path = ''` and uses schema-qualified names.
- Server-side checks are the authority for bounds, palette range and cooldown. Client checks are only for UX.

## Never without asking the user

- `supabase db push`, `supabase link`, or any command against the **hosted** project.
- Editing a migration that may already be applied. Add a new migration instead.
- Adding or upgrading a dependency, or anything on the "Not used" list above.
- Paid services, new third-party backends, or anything that breaks the free-tier constraint.
